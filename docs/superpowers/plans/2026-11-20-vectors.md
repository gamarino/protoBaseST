# protoBaseST Vector Indexes and Vector Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port `proto_db` `v2.0.0rc4`'s vector feature (VectorIndex with exact, ivf_flat and maintained-only hnsw backends, `near[]`, VectorSearch, the planner's near rules) to protoBaseST on the same disk format, node-identical, and release it as protoBaseST 0.4.0.

**Tech Stack:** protoST (pinned in Task 1), protoCore 3.6.1, protoIO 0.7.0; `proto_db` `v2.0.0rc4` with CPython 3.14 (numpy blocked for identity tests) for interop.

## Global Constraints

- Every Global Constraint of `docs/superpowers/plans/2026-11-18-indexed-queries.md` applies, except where Addendum V changes it: vector indexes are now ported (the refusal narrows to hnsw **search**, ruling VQ1), and protoST changes are allowed only as VP under ruling VQ2. protoCore is never changed.
- `proto_db` is the reference at `v2.0.0rc4`, read only via `git -C "$PROTOBASE_REPO" show v2.0.0rc4:<path>`; every difference is a `docs/deviations.md` entry.
- Same bytes: format 4, no new record type or field; trees node-identical to `proto_db`'s for the same operations; IVF training identity is against `proto_db` without numpy, on the same host libm.
- Everything immutable; mutable state only through `Atom`; no mutexes.
- TDD with fail-first evidence in the commit body; each task runs its own tests; full suite, soaks and audits once in the final task.
- No timing-dependent tests; benchmarks serial on a quiet machine, self-verifying, peak RSS reported, nothing asserted about time, differences under ~15% are noise.
- Documentation in the same task as the code; course-material form; unmeasured figures marked `[measured in V<n>: ...]`, never invented. Professional English.
- Naming: the Python product is `proto_db`; protoBaseST is never called a GemStone "successor"; the pitch is same answers, plans and bytes, never speed.
- No approval stops (ruling in section 8 of the addendum); decisions go to `docs/decisions.md` with evidence.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Maintainer environment rules: no rm / git clean / worktree remove; no pkill; temporary files in the session scratchpad.

## Review Focus

1. A collection with a vector index written by protoST must validate in `proto_db` and vice versa after every mutator, merge and stale rebuild.
2. Non-finite, NaN, signalling-NaN Decimal and huge-integer components are refused exactly where `proto_db` refuses them.
3. Ties in distance order resolve exactly as `proto_db` (rank order, insertion order).
4. An hnsw-indexed collection is writable and validated, but any execution of a `VectorHnsw` plan raises `PBNotSupportedError`.
5. A retrain inside a merge or cluster round preserves identity and does not leave a stale index on conflict/retry.
